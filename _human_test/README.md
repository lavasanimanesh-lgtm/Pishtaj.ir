# زیرساخت تست شبیه‌سازی‌شده انسانی (AI-Persona)

## هدف
بررسی عملکرد واقعی نرم‌افزار از دید کاربران شرکت PTF، قبل از اتکای سازمانی به ریلیز.

## اجزا
| مسیر | نقش |
|:---|:---|
| `_personas/*.json` | ۱۰ کاربر فرضی با نقش و تمرکز |
| `_human_test/templates/` | قالب سناریو / چک‌لیست / گزارش |
| `_human_test/vX.Y/` | بسته هر دوره تست (سناریو+گزارش) |
| `_tools/human/run-persona-gate.js` | گیت اجباری هر ۵ اسپرینت |
| `BACKLOG-HUMAN-TEST-FINDINGS.md` | باگ/پیشنهاد تأیید جمعی |
| `HUMAN-TEST-REPORT-vX.Y.md` | گزارش دوره |

## قانون مصوب کارفرما (v21.4)
**بعد از هر ۵ اسپرینت، تست عملکرد شبیه‌سازی‌شده انسانی الزامی است.**

شمارنده: `settings` در `_tools/human/sprint-counter.json` یا از روی VER/اسپرینت‌های handover.

### حداقل الزامات هر gate
1. حداقل **۵** کاربر فرضی (ترجیح ۱۰)
2. پوشش ماژول‌های لمس‌شده در ۵ اسپرینت اخیر + **مسیرهای حیاتی دائمی** (login، ثبت/ویرایش پیشنهاد، درخواست، مشتری، تامین، پرونده فروش، مالی پایه)
3. رضایت جمعی از عملکرد صحیح امکانات تست‌شده
4. ثبت باگ‌ها و پیشنهادات UX در `BACKLOG-HUMAN-TEST-FINDINGS.md` به‌صورت US/BUG جدید
5. بدون gate سبز → ریلیز production توصیه نمی‌شود (می‌توان zip داخلی ساخت ولی HANDOVER باید gate را قرمز ثبت کند)

## اجرای سریع
```bash
node _tools/human/run-persona-gate.js --version v21.4 --force
# خروجی: _human_test/v21.4/ + HUMAN-TEST-REPORT-v21.4.md + به‌روزرسانی backlog
```
